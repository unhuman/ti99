; Keystone Kapers -- the biplane, FRAME 1 of 2. Facing RIGHT.
;
;   #   the plane        .   the shop floor showing through
;
; The grid is 16 wide by 16 tall. Edit the 16 rows at the bottom and hand the
; file back; every line that is exactly 16 of '#' and '.' is read as art, and
; everything else (these ; lines, blank lines, the ruler, your notes) is
; ignored -- so annotate as freely as you like.
;
; THE TWO FRAMES ARE THE WHOLE ANIMATION. draw_obst alternates them every four
; passes. They should differ ONLY in the propeller: anything that changes in
; the body as well reads as the plane itself twitching rather than as a blade
; going round.
;
; RULES THE HARDWARE IMPOSES:
;
;  1. ONE COLOUR. The entire plane is a single sprite in one colour, so there
;     is no black cockpit and no second tone available -- '#' or nothing.
;     (It was two sprites until recently; the second one cost a scanline slot
;     and could be dropped by the VDP, on the one obstacle that kills.)
;
;  2. DRAW THE RIGHT-FACING FRAME ONLY. The left-facing one is generated by
;     mirroring this, because the VDP has no flip bit.
;
;  3. THE BOTTOM EDGE MUST STAY ON ROW 15. Every obstacle's foot is at y + 16,
;     so a plane drawn to row 13 would fly two pixels higher than the game
;     thinks it does. Empty rows at the TOP are free.
;
;  4. HEIGHT DRIVES THE HITBOX. It currently occupies rows 6-15, ten pixels,
;     and the game has that written down as 20..30 above the floor. Change the
;     number of drawn rows and say so -- I move `oht` to match, or the player
;     gets hit by air above the plane.
;
;  5. WIDTH IS FREE up to the full 16.
;
; WHAT I KEEP GETTING WRONG, so you know what to aim at: the propeller's
; balance about the fuselage. The body is two solid rows (9 and 10), but the
; nose only reaches column 14 on row 10 -- so "centred" reads differently
; depending on which of those you take as the axis, and I have now been wrong
; in both directions. Draw it where it looks right and that settles it.
